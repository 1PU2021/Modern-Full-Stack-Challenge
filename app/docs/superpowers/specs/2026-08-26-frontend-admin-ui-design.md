# Frontend/Admin UI Design

## Goal

Add a small React/Vite administrator UI that demonstrates the existing
authenticated intake, fanout, and dispatch pipeline without changing backend
contracts or adding production authentication.

## Scope and screens

The frontend is a standalone package under `app/web/`. It has four reachable
views:

1. **Compose** — title, body, priority, SMS/email channel checkboxes, and a
   group or polygon target. Groups are loaded from `GET /api/v1/groups`.
2. **Alerts** — newest-first alerts from `GET /api/v1/alerts`, with loading,
   empty, and error states and links to detail.
3. **Alert detail** — alert metadata/body/target, canonical delivery counts,
   recipient delivery rows, manual refresh, and two-second polling while the
   alert remains non-terminal.
4. **Groups** — group names and numeric member counts, also reused by Compose.

A compact header provides navigation and a clearly labelled development token
field/settings panel. There is no login, signup, user management, or role
administration.

## Client architecture

`src/api.js` is the only network boundary. It centralizes the configurable API
base URL (`VITE_API_BASE_URL`, default `/api`), bearer-token storage, JSON
request/response handling, and conversion of non-2xx responses into errors that
retain the backend's public `code`, `message`, and `details` fields.

`src/App.jsx` owns the selected view, token state, shared alerts/groups data,
and refresh callbacks. Components use ordinary React state and effects; no
Redux, Zustand, React Query, component framework, or generated client is
needed.

## Alert payloads

Compose performs lightweight usability checks and relies on the backend as the
authoritative validator. It disables submission while a request is in flight,
sets an `Idempotency-Key` generated in the browser, and displays the accepted
alert id/replay result.

Group submissions send:

```json
{"target":{"type":"group","groupId":"<uuid>"}}
```

Polygon submissions send standard GeoJSON:

```json
{"target":{"type":"polygon","geojson":{"type":"Polygon","coordinates":[...]}}}
```

## Polygon UX

Polygon mode uses MapLibre GL JS with OpenFreeMap tiles and Terra Draw's
polygon mode. The map is centered on the deterministic seeded demo area and a
`Demo polygon` control loads a known polygon that intersects seeded recipients.
The resulting GeoJSON is displayed in a compact read-only field for demo
transparency and is submitted unchanged. No paid map account, geocoder, or
external application service is required.

## Authentication and local integration

The token panel accepts a development JWT generated by
`docker compose run --rm seed npm run token ...` (or pasted from another
source). A browser refresh may retain the token in `sessionStorage`; the UI
labels it development-only and never handles secrets or passwords.

Vite proxies `/api` to `http://localhost:3000` during development. Compose
adds an optional `web` service built from `app/web` that exposes port 5173 and
uses the same proxy target, while `npm run dev` from `app/web` remains the
fastest local workflow.

## Visual and error behavior

Plain CSS provides a responsive two-column desktop layout that collapses to a
single column on narrow screens. Status badges use the exact backend values:
`pending`, `delivered`, `failed`, `rate_limited`, and `timed_out`; counts render
in that canonical order. Forms, lists, maps, and detail tables have explicit
loading, empty, validation, authentication, and server-error states. No
animation or design-system abstraction is introduced.

## Testing

Vitest and Testing Library cover API authorization/error handling, compose
serialization for group and polygon targets, submit locking, loading/error
states, status/count presentation, and detail polling lifecycle. A Vite
production build is required. The existing backend unit/integration/lint
suites remain unchanged. The real local Compose smoke path remains the
acceptance proof for asynchronous delivery; the frontend adds a lightweight
configurable smoke checklist rather than a browser automation stack.

## Non-goals

No backend route changes, production authentication, external paid map APIs,
real provider integrations, frontend state framework, frontend Docker image
complexity, or unrelated infrastructure work.
